# 鎏光MrdT相册

**Liuguang MrdT Gallery** —— 单文件 PHP 相册，无需数据库、无需安装，上传即用。

> 整合 Lychee（灯箱 / EXIF / 极简颜值）、Piwigo（分类 / 检索 / 收藏）、FilePress（直链 / 文件元数据）
> 三家开源相册的优点，收敛成一个 `index.php`。


---

## 一、30 秒部署

1. 宝塔新建站点（PHP **7.4 ~ 8.5** 均可，无需任何扩展也跑得动；有 GD 更快）
2. 把 `index.php` 上传到站点根目录
3. 图片按文件夹放好：

```
/www/wwwroot/album/
├── index.php
├── 2026·秋行/
│   ├── 海上落日.jpg
│   └── 雪山晨光.jpg
├── 山水写意/
│   └── 湖光倒影.jpg
└── 随手拍.jpg            ← 根目录散图自动归入「未分类」
```

4. 浏览器打开域名即用。**首次打开有约 2.4 秒鎏光开场**：旋转鎏金光束 + 光圈刻度环
   + 三轨流光粒子 + 扫光金字标题，谢幕时金色闪光爆开、光环旋散。光环期间
   加载并发自动拉满、首屏 + 次屏缩略图全速预载，光环落下即是完整画面。
   开场只展示一次（localStorage 记忆），想再看一遍访问 `?splash` 即可。

## 二、功能一览

| 类别 | 能力 |
|---|---|
| **图片格式** | JPEG / JFIF / PNG / GIF / WebP / **AVIF** / BMP / **HEIC / HEIF** 全格式入册；GD 解不了的由 ffmpeg 抽帧兜底，前端还有「缩略图 → 原图 → 占位纹」三级降级，任何格式都不会破图 |
| **动图** | GIF / APNG / 动态 WebP：纯 PHP 解析块结构判定动画，卡片静态首帧 + 「动图」角标，悬停单张即播；有 ffmpeg 自动转 MP4 播放（体积约 1/10），透明动图不转码保画质（详见「动图支持」） |
| **实况照片** | iPhone Live Photo（HEIC/JPG + 同名 MOV）自动配对成一条记录，MOV 不再单独成卡；卡片带 LIVE 徽标，灯箱**按住播放、松手回到静帧**（详见「实况照片」） |
| **分类** | 自动扫描子文件夹成相册；根目录散图归「未分类」并排在最后 |
| **视频** | mp4 / webm / mov / m4v / ogv：封面帧 + 时长角标 + 灯箱原生播放（详见「视频支持」） |
| **视图** | 瀑布流（4→3→2→1 列自适应）/ 等高网格（按行对齐、不裁图）/ 时间轴杂志（按日期分组、参数铺在照片下方），三视图即点即切，选择自动记住；也支持 `?view=grid`、`?view=timeline` 直链指定 |
| **模式** | 按相册分区 ↔ 全部照片平铺，双模式 |
| **检索** | 实时搜索（匹配文件名 + 相册名，130ms 防抖） |
| **排序** | 名称 / 体积 × 升序 / 降序；**时间排序仅在时间轴视图出现**（时间轴必须顺时间读，其他视图提供时间序没有意义） |
| **收藏** | 卡片角标或灯箱内 `F` 键收藏，localStorage 持久化，可「只看收藏」 |
| **灯箱** | 左右切换、键盘 `←` `→`、`Esc` 关闭、触屏滑动、点击图片 1:1 缩放 |
| **信息** | EXIF 拍摄参数（相机/镜头/光圈/快门/ISO/焦距/曝光补偿/拍摄时间/GPS/海拔）+ 文件元数据（尺寸/体积/修改时间/相对路径） |
| **分享** | 一键下载原图、一键复制直链（中文/空格文件名安全编码） |
| **主题** | 跟随系统 → 浅色 → 深色 三态循环，选择存 localStorage |

|---|---|

| `空格` | 播放 / 暂停（视频）；播放 / 停止实况（实况照片） |
| `按住画面` | 实况照片：按住播放动态，松手回到静帧（iOS 原生手感） |

## 三、缓存机制与加载速度

### 缓存是怎么进行的

```
浏览器请求 ?t=<key>&w=640
        │
        ├─ 命中 .cache/<md5(路径|宽度|mtime)>.webp → 直接吐出，零计算
        │
        └─ 未命中 → GD 现场缩放（HEIC/动图 WebP/裁剪版 GD 的 AVIF 先由 ffmpeg 抽首帧）
                  → 写 .tmp 再 rename（原子写入，并发不留半张坏图）
                  → 吐出；下次访问零计算
```

- **缓存 key 含文件 mtime**：原图被替换/更新后旧缓存自动失效重建，无需手工清理；
  新增图片自动进入同一流程。
- **两档宽度**：卡片 640px、灯箱 1600px，各存一份；质量 82。
- **WebP 自动协商**：浏览器 `Accept` 含 `image/webp` 就出 WebP（比 JPEG 小 20-30%），
  老浏览器自动回退 JPEG，并复用另一格式现成缓存避免重复生成。
- **元数据同样缓存**：EXIF / 视频参数 / 动图探测结果都在 `.cache/meta/`、`.cache/anim/`，
  原子写入，`--warm` 一并预热。

### 如何保证载入速度

1. **预热把生成挪出用户请求**（三条路，可叠加）：
   - 页面自触发：首个访客打开页面后，页面**先完整送达**，PHP 进程再用剩余时间
     （fastcgi_finish_request，最多 12 秒/次）后台补齐缓存，全部完成记 `warm_done` 后零开销跳过；
   - CLI 手动：`php index.php --warm`（增量，重复跑只处理新图）；
   - 宝塔计划任务：每天凌晨跑一次同上命令即可。
2. **有序并发加载器**：每个相册前 2 张作封面优先并行 → 其余进入视口前 700px
   按文档顺序入队 → 并发上限 6，无惊群；顶部鎏金光条实时显示已载进度。
3. **首访光环加速**：开场的 2.4 秒里并发临时提到 12，并把前 30 张一次性入队，
   用户看到第一屏时图片已经在了。
4. **灯箱带宽让渡**：打开灯箱暂停列表加载，带宽让给大图；关闭自动恢复。
5. **零布局抖动**：服务端预置每张图宽高（已按 EXIF 方向校正），骨架屏与成图
   尺寸完全一致（CLS = 0），页面不跳。
6. **页面体积**：单页全量输出 16 张时 HTML 约 113 KB（内联全部 CSS/JS，零外部请求）；
   图片全部走缓存后的 WebP 缩略图，单张通常 5-30 KB。

**实测吞吐**（2 核 2G，单张 4000×3000 手机照片）：

| 规模 | 冷启动预热耗时 | 缓存占盘 | 预热后首屏 |
|---|---|---|---|
| 200 张 | 1-2 分钟 | ~40 MB | 接近瞬开 |
| 1000 张 | 5-10 分钟 | ~150-400 MB | 接近瞬开 |
| 5000 张 | 30-50 分钟 | ~1-2 GB | 接近瞬开 |

## 四、可靠性设计

| 机制 | 说明 |
|---|---|
| **原子写入** | 缩略图先写 `.tmp` 再 `rename`，并发或中断永远不会留下半张坏图；EXIF 参数缓存同样原子写入 |
| **批量参数接口** | `?x=key1,key2,...` 一次最多 60 张，时间轴一屏一个请求；单张 `?x=key` 行为不变 |
| **内存自调** | 生成前自动把 `memory_limit` 提到 512M（已是 -1/更高则不动），12000×9000 全景图不再崩 |
| **三级降级链** | 缩略图失败 → 自动换原图重试 → 仍失败 → 深浅色自适应占位纹，永不出现破图图标；视频封面失败 → 占位封面（比例不变） |
| **路径安全** | 缩略图/元数据/动图接口走 base64url + `realpath` 白名单校验，目录穿越返回 404 |
| **EXIF 方向** | 按 Orientation 自动旋转，手机竖拍不歪；PNG 透明区压白底 |

> **等高网格的实现**：不是把图裁成方块，而是"按行对齐的相片墙"——每行等高、
> 左右铺满，图片保留原始宽高比不被裁切；末行只剩一两张时也保持同一行高，
> 不会被拉伸放大。与瀑布流共用同一套卡片语言（16px 间隙 / 16px 圆角 / 同样的悬停），
> 只是排版方式不同：瀑布流竖向错落，网格横向对齐。

### 时间轴杂志（第三视图）

按拍摄日期分组的编辑式长列表：

- **日期分组**：按文件时间分组，吸顶的日期大字 + 左侧时间轴导轨 + 鎏金节点；
  切进该视图时自动切到"时间 ↓"并提示（**时间排序只在这个视图出现**）。
- **图片版**：图片保持原始比例居中——竖构图自然收窄、横构图自然铺满，杂志式节奏感。
- **参数行**：相机 / 镜头 / 焦距 / 光圈 / 快门 / ISO / 曝光补偿直接铺在照片下方；
  动图 / 实况 / 视频有金色类型小标；有 GPS 时坐标是金色链接，点开在手机地图查看
  （WGS84 坐标直传，不偏移）；没有参数的图显示像素尺寸 + 一句说明，不留空白。
- **性能**：参数按屏批量拉取（一次 24 张），服务端带磁盘缓存，翻回看过的照片零请求。

## 五、动图支持（GIF / APNG / 动态 WebP）

**判定**：纯 PHP 解析容器块结构（GIF 的 GCE/NETSCAPE 块、APNG 的 acTL/fcTL、
WebP 的 VP8X/ANIM/ANMF），只读文件头几 KB，不解码、不依赖任何扩展；
结果带 mtime 签名缓存到 `.cache/anim/`。

**卡片**：永远是静态首帧 + 左下「动图 · 时长」角标（鎏金呼吸点）；
鼠标悬停单张即播（视频源或原图，视服务器条件），移开即停，
一屏几十个动图也不会同时抢解码资源；触屏设备自动禁用悬停播放。

**灯箱播放，按服务器条件二选一**：

| 条件 | 播放方式 | 说明 |
|---|---|---|
| 有 ffmpeg 且无透明通道、时长 ≤ 60s | 转 MP4（H.264 + faststart）循环静音自动播 | 体积约降至 1/10，走 `.cache/anim/*.mp4` 缓存 + `?a=` 接口（支持 206 分段） |
| 透明动图 / 超长 / 无 ffmpeg | 直接加载原动图 | 动画零损耗；透明区域绝不被压成黑块 |

> 透明判定用的是「实测像素」而非容器标志位：ffmpeg 抽 10 帧读 alpha 最小值，
> 避免编码器为帧差优化设置的假透明标志把好图误判成透明图。

**实况照片（iPhone Live Photo）**：同一目录下同名的 HEIC/JPG + MOV 自动配对成一条记录：

- MOV 不再单独成卡（同名 JPG 与 HEIC 都有时，两者都获得 LIVE 能力）；
- HEIC 静帧 GD 解不了 → 借配对 MOV 抽首帧当封面，画面与静帧一致；
- 卡片左上角 LIVE 同心圆徽标（对齐 iOS 原生观感）；
- 灯箱里**按住画面播放动态、松手回到静帧**，`空格` 等价；底部鎏金进度条指示播放进度；
- 配对信息、动态时长同样入缓存，`--warm` 输出配对统计。

## 六、视频支持

mp4 / webm / mov / m4v / ogv 可以和图片混排在同一个相册里：卡片显示**封面帧 + 时长角标 +
播放键**，灯箱用浏览器原生播放器（`空格` 播放暂停、`←→` 切换），时间轴视图的参数行显示
**时长 / 分辨率 / 帧率 / 视频编码 / 音频 / 码率 / 容器 / 创建时间**。

**三层探测，按服务器条件自动降级**：

| 服务器条件 | 封面帧 | 时长 / 尺寸 / 编码 |
|---|---|---|
| ffmpeg + ffprobe 都有 | ffmpeg 抽第 1 秒（片头黑场避让），走与图片相同的 GD 缩放 + 原子写入缓存 | ffprobe，最准 |
| 只有 ffmpeg | 同上 | 纯 PHP 解析 mp4/mov 的 moov（mvhd/tkhd/stsd），只 seek 几 KB、不解码 |
| 都没有（或 `shell_exec` 被禁用） | 卡片显示占位封面（比例仍按真实尺寸，版面零跳动） | 同上；webm 等格式退回 16:9 占位 |

无论落在哪一层，**播放都不经过 PHP**：灯箱直接用原文件直链，由 nginx 处理 `206` 分段请求，
长视频拖进度条不占 PHP-FPM 资源。

**宝塔开启抽帧（可选，三步）**：

1. 软件商店安装 ffmpeg（或 `yum install -y ffmpeg` / `apt install -y ffmpeg`）
2. PHP 设置 → 禁用函数：移除 `shell_exec`、`exec`、`proc_open`、`popen`
   —— 宝塔默认禁用它们；不移除也能用，只是自动降到"占位封面"层，其余功能不受影响
3. 跑一次 `php index.php --warm`，输出会报告当前探测层与视频/动图/实况解析统计

**设计取舍**：

- 卡片永远只放静态封面，播放只发生在灯箱 —— 一屏几十个 `<video>` 元素在 2G 内存服务器
  和 iOS 上都是灾难，这是唯一稳的形态
- 损坏 / 无法解析的视频：封面请求返回 404 → 前端自动换成占位封面；元数据安全退回（只显示容器名），
  绝不把二进制当图片吐给浏览器
- mp4 建议转成 faststart（`ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4`），
  moov 挪到文件头，浏览器秒出画面；纯 PHP 解析对 moov 在头在尾都能读
- 视频文件大，先算磁盘与流量账：2H2G 轻量服务器建议单文件 ≤ 500MB

## 七、配置

编辑 `index.php` 顶部的 `$CONFIG`：

```php
$CONFIG = [
    'brand'       => '鎏光MrdT相册',   // 页面标题 / 顶栏 / 页脚品牌名
    'brand_short' => '鎏光MrdT',
    'desc'        => '单文件驱动的本地相册 · 瀑布流 · 原图可下载',
    'cache_dir'   => __DIR__ . '/.cache',  // 缩略图缓存目录
    'thumb_w'     => 640,             // 卡片缩略图宽（视频封面帧同宽）
    'view_w'      => 1600,            // 灯箱大图宽（视频大封面同宽）
    'quality'     => 82,              // 压缩质量（1-100）
    'allowed_ext' => ['jpg','jpeg','jfif','png','gif','webp','avif','bmp','heic','heif'],
    'video_ext'   => ['mp4','webm','mov','m4v','ogv'],
    'anim_ext'    => ['gif','png','webp'],   // 可能含多帧动画的格式
    'live_still'  => ['jpg','jpeg','heic','heif'],  // 可与同名 MOV 配成实况照片的静帧
    'live_movie'  => 'mov',                  // 实况照片的动态部分扩展名
    'anim_max_sec'=> 60,              // 动图超过此秒数不转 MP4（保护低配服务器）
    'ffmpeg'      => '',              // 留空自动探测；装在非常规路径时在此填写
    'ffprobe'     => '',              // 留空自动探测（通常与 ffmpeg 同目录）
];
```

> 想 rename 品牌：只改 `brand` / `brand_short` 两项即可，页面标题、顶栏、页脚、favicon 会一起变。

## 八、服务器侧检查清单

```bash
# 1. 缓存目录必须可写（PHP-FPM 以 www 运行）
chown -R www:www /www/wwwroot/album

# 2. 想要手机竖拍自动转正，需启用 exif 扩展（宝塔 → PHP 设置 → 安装扩展 → exif）
#    没有该扩展也能正常用，只是竖拍图不会自动转正

# 3. 宝塔站点设置开启 HTTP/2（需 SSL），缩略图小文件多路复用收益明显
```

**排查某张图加载失败**：直接在浏览器单独打开它的缩略图地址
`index.php?t=<key>&w=640`，报错一目了然；或先跑一次 `--warm`，失败文件会逐行列出。

## 九、与技术方案的取舍说明

| 曾评估的方案 | 结论 |
|---|---|
| Immich / PhotoPrism / LibrePhotos | 需 Docker + 4-8G 内存，2H2G 跑不动 ML 索引 → 排除 |
| Piwigo | 功能全、网页向导安装，但需要 MySQL + 常驻 200-400MB → 作为备选，见 `../Piwigo宝塔安装教程.md` |
| Lychee | Laravel 部署链长、权限易踩坑 → 作为备选，见 `../Lychee宝塔安装教程.md` |
| FilePress | 存在 PHP 8 下的 `sprintf` 格式符崩溃缺陷 → 排除 |
| **本方案** | **零依赖、零数据库、零安装，吸收以上各家优点** |
